# Проверка местных моделей для работы с кодом

Здесь собран практический ответ на простой вопрос: какую модель можно запускать
на одном компьютере с Windows 11 и Radeon RX 6800, чтобы Claude Code не только
отвечал, но и действительно работал с файлами.

## Короткий ответ

Для основной очереди остаётся `qwen3:8b-q4_K_M-ctx40k`.

Из двух свежих и необычных гостей стоит оставить
`ministral-3:8b-ctx32k`. Он не идеален, но умеет работать с файлами и полностью
помещается в видеопамять.

`nemotron-3-nano:4b-ctx32k` пока отклонён. Он очень лёгкий и быстрый, но трижды
не понял задачу. Получился резвый собеседник вместо помощника программиста.

## Как мы сюда пришли

Сначала мы проверяли очевидных кандидатов. Затем выяснилось, что размер модели
говорит не всё. Важен ещё размер рабочего окна: слишком большое окно съедает
память, и часть работы переезжает в обычную память компьютера. После этого
скорость начинает гулять.

Поэтому для каждой модели появилась своя настройка:

| Модель | Рабочее окно | Размещение | Итог |
|---|---:|---|---|
| `qwen3:8b-q4_K_M-ctx40k` | `40960` | `100% GPU` | Основной кандидат |
| `granite4.1:8b-ctx32k` | `32768` | `100% GPU` | Надёжный запасной кандидат |
| `gemma4:e4b-ctx128k` | `131072` | `100% GPU` | Быстрая, но нестабильная в длинной работе |
| `ministral-3:8b-ctx32k` | `32768` | `100% GPU` | Новый интересный кандидат |
| `nemotron-3-nano:4b-ctx32k` | `32768` | `100% GPU` | Пока отклонён |

`GPU` в таблице означает видеокарту. Правило строгое: если модель начинает
выгружаться в обычную память, в следующий круг она не проходит.

![Размер настройки в видеопамяти](docs/assets/model-gpu-footprint.png)

## Два гостя с боковой двери

### Ministral 3 8B

Почему взяли: модель свежая, рассчитана на работу рядом с пользователем и
заявляет встроенные вызовы средств. В каталоге Ollama у семейства около
`1.1M` загрузок.

Что получилось:

| Этап | Время | Итог |
|---|---:|---|
| Точный ответ | `43.4` с | Пройден |
| Запуск команды | `78.2` с | Пройден |
| Работа с файлами, первая попытка | `206.7` с | Почти пройден: пропущено чтение `CHANGELOG.md` |
| Работа с файлами, повтор | `219.5` с | Пройден полностью |

Модель умеет читать файлы, создавать новый файл, запускать команды и проверять
состояние Git. На первой попытке она поспешила и пропустила один обязательный
шаг. На второй собралась и сделала всё по списку.

Вывод: оставить в очереди для задач с кодом, но следить за повторяемостью.

### Nemotron 3 Nano 4B

Почему взяли: свежая гибридная модель NVIDIA, маленькая и необычная по
устройству. В каталоге Ollama у семейства около `428K` загрузок за первый
месяц.

Что получилось:

| Этап | Время | Итог |
|---|---:|---|
| Точный ответ | `26.1` с | Не пройден |
| Запуск команды | `51.8` с | Не пройден |
| Работа с файлами | `19.8` с | Не пройден |

Модель полностью помещается в видеопамять: всего `5.7` ГБ. Но вместо выполнения
задания она просит уточнить, чем помочь. Экономия памяти прекрасна, однако
отвёртка всё-таки должна крутить винты.

Вывод: не использовать с Claude Code на текущем стенде.

![Этапы с первой попытки](docs/assets/model-first-attempt-score.png)

## Кто быстрее в сложной работе

Сравниваем только успешные проходы работы с файлами. Провал за три секунды не
является рекордом скорости, как бы заманчиво это ни выглядело в таблице.

![Время успешной работы с файлами](docs/assets/model-successful-agent-time.png)

`qwen3:8b-q4_K_M-ctx40k` остаётся самым ровным выбором. Granite медленнее, зато
предсказуем. Ministral уже заслужил место в следующем круге: чуть медленнее
Granite и с одной осечкой, но это осечка рабочего помощника, а не пустой ответ.

## Что делать дальше

1. Прогнать `qwen3:8b-q4_K_M-ctx40k`, `granite4.1:8b-ctx32k` и
   `ministral-3:8b-ctx32k` на небольшом наборе задач с тестами.
2. Для Ministral считать долю успешных повторов, а не один красивый проход.
3. Gemma оставить для ограниченных задач и отдельно разбирать остановку после
   первого чтения файла.
4. Nemotron пока оставить за дверью. Он быстрый, но принёс не тот чемодан.
