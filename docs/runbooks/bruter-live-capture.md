# Bruter Live Capture Runbook

## Purpose

Use this runbook to capture the exact Ollama HTTP traffic generated by a live IDE run from `Claude Code for VS Code`.

This is the next debugging step after the findings in [bruter-api-debug-2026-06-01.md](../runbooks/bruter-api-debug-2026-06-01.md).

## Prerequisites

- `ssh-agent` access to `root@bruter`
- `tcpdump` installed on `bruter`
- active IDE validation target, preferably:
  - `llama3.2:latest`
  - or `qwen3:8b-q4_K_M`

## Start Capture

From the repo root:

```bash
tools/bruter_ollama_capture.sh start llama32
```

This prints:

- remote `.pcap` path
- remote `.pid` path

Record the `.pcap` path in the active run record before starting the IDE run.

## Run The IDE Scenario

While capture is active:

1. Open the active run record.
2. Start a fresh Claude Code session in VS Code.
3. Paste the exact acceptance prompt.
4. Let the agent respond without manual assistance.

Recommended active record:

- [docs/runbooks/runs/2026-06-01-run-002-llama3.2-latest.md](../runbooks/runs/2026-06-01-run-002-llama3.2-latest.md:1)

## Stop Capture

After the IDE response is complete:

```bash
tools/bruter_ollama_capture.sh stop /tmp/ollama-capture-YYYYMMDDTHHMMSS-llama32.pcap
```

This stops `tcpdump` on `bruter` and prints the remote file size.

## Inspect The Capture Quickly

For a plaintext spot check:

```bash
ssh root@bruter "tcpdump -nn -A -r /tmp/ollama-capture-YYYYMMDDTHHMMSS-llama32.pcap | sed -n '1,260p'"
```

Look for:

- exact `POST /v1/messages` body from the IDE
- tool definitions actually sent by the client
- raw HTTP response body returned by Ollama

## What To Compare

Compare three things:

1. the IDE prompt you intended to send
2. the exact request body actually sent by the IDE
3. the exact HTTP response body returned by Ollama

This will tell us whether the problem is:

- prompt mutation in the IDE client
- missing tool definitions
- extra hidden instructions
- or genuine model behavior under the actual request

## Update The Run Record

After the capture:

- write the `.pcap` path into the run record
- note whether the IDE text matched the raw HTTP response
- classify the failure using [vscode-ollama-failure-taxonomy.md](../archive/early-vscode-validation/vscode-ollama-failure-taxonomy.md)
